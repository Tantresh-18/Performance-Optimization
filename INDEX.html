Image Lazy Loading + WebP

Images are loaded only when they enter the viewport using the native loading="lazy" attribute and Intersection Observer API. WebP format reduces file sizes by up to 30% vs JPEG while maintaining quality.

Technique 1

Lazy Loading + Modern Image Formats

Scroll down to watch images load on-demand using Intersection Observer. Each image also shows its simulated format (WebP / AVIF).

Implementation Code

// Native lazy loading (supported in all modern browsers)
<img src="image.webp"
     loading="lazy"
     decoding="async"
     width="800" height="600"
     alt="..."
>

// Intersection Observer for custom lazy logic
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src; // swap real src in
      observer.unobserve(img);
    }
  });
}, { rootMargin: '200px' }); // preload 200px before viewport

document.querySelectorAll('img[data-src]').forEach(img => observer.observe(img));

Technique 2

Caching Strategies

Different resource types deserve different cache strategies. Here's how a well-optimized app categorizes its assets.

Network Requests — Optimized Cache Headers

Resource Cache Strategy Max-Age Status

Cache-Control Header Examples

# Static assets with content hash — cache forever, invalidate by filename
Cache-Control: public, max-age=31536000, immutable

# HTML pages — revalidate every request
Cache-Control: no-cache, must-revalidate

# API responses — short cache, allow stale while revalidating
Cache-Control: public, max-age=60, stale-while-revalidate=300

# Service Worker caching strategy (Cache First)
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request).then(cached =>
      cached || fetch(event.request).then(response => {
        const clone = response.clone();
        caches.open('v1').then(cache => cache.put(event.request, clone));
        return response;
      })
    )
  );
});

Technique 3

Eliminate Render-Blocking Resources

Render-blocking scripts and stylesheets delay the First Contentful Paint. The timeline below shows the loading order before and after optimization.

Non-Blocking Script Loading

<!-- WRONG: blocks HTML parsing -->
<script src="heavy-lib.js"></script>

<!-- RIGHT: defer – runs after DOM parsed, in order -->
<script src="app.js" defer></script>

<!-- RIGHT: async – loads in parallel, runs immediately when ready -->
<script src="analytics.js" async></script>

<!-- Non-blocking CSS: load async using print media trick -->
<link rel="stylesheet" href="non-critical.css"
      media="print" onload="this.media='all'">

<!-- Preload critical resources -->
<link rel="preload" href="hero.webp" as="image">
<link rel="preconnect" href="https://fonts.googleapis.com">
